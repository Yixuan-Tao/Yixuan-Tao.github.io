# 风暴英雄经验系统拆解文档

## 一、目标定位

**一句话总结：** 风暴英雄采用团队共享经验系统，将个人成长转化为团队协作，通过降低个体差异来提升团队博弈的深度与观赏性。

### 核心目标
- **消除滚雪球效应**：避免传统MOBA中个人优势快速转化为团队碾压
- **强化团队协作**：让辅助、坦克等非核心输出角色也能获得完整成长体验
- **降低学习门槛**：新手玩家不会因为对线劣势而彻底失去游戏参与感
- **提升比赛节奏**：缩短发育期，更快进入团战博弈阶段

### 目标用户
- **新手玩家**：降低挫败感，即使被压制也能通过团队贡献获得成长
- **核心玩家**：享受更高层次的团队策略博弈，而非个人操作秀
- **电竞观众**：比赛更注重团队配合，观赏性和可预测性更强

---

## 二、核心循环

**一句话总结：** 团队通过地图目标、小兵、野怪、英雄击杀共同积累经验，全员同步升级解锁天赋，形成"团队协作→共享成长→天赋策略→团队博弈"的循环。

### 传统MOBA vs 风暴英雄对比

| 维度 | 传统MOBA（LOL/Dota2） | 风暴英雄 |
|------|----------------------|----------|
| 经验归属 | 个人独立计算 | 团队共享 |
| 升级节奏 | 个体差异化，1-18级 | 全员同步，1-20+级 |
| 成长方式 | 装备+技能等级 | 天赋系统 |
| 滚雪球效应 | 强，个人优势快速扩大 | 弱，团队优势需持续积累 |
| 辅助体验 | 经济经验双重劣势 | 与输出位平等成长 |

### 核心循环图示

```
[团队协作] → [获取经验] → [全员升级] → [选择天赋] → [团队博弈]
    ↑                                                    ↓
    └──────────────── [反馈调整] ←──────────────────────┘
```

**关键环节说明：**

1. **团队协作**
   - 玩家视角：无论对线、打野、争夺目标，所有行为都为团队贡献经验
   - 开发视角：经验来源统一计算，无需区分个人贡献权重

2. **获取经验**
   - 玩家视角：看到团队经验条增长，感受到集体进步
   - 开发视角：经验池统一管理，根据活动类型分配经验值

3. **全员升级**
   - 玩家视角：所有人同时升级，获得新技能或天赋选择
   - 开发视角：触发升级事件，同步推送天赋UI

4. **选择天赋**
   - 玩家视角：根据局势选择强化方向，体现策略深度
   - 开发视角：天赋树系统，每级提供3-5个可选项

5. **团队博弈**
   - 玩家视角：基于天赋组合进行团战，体验策略对抗
   - 开发视角：平衡天赋强度，确保多样性

## 三、功能框架

**一句话总结：** 经验系统由经验池、升级机制、天赋系统三部分组成，通过团队共享、同步升级、天赋分支实现差异化成长。

### 3.1 经验池子系统

**功能描述：**
- 统一管理团队经验值
- 多渠道经验来源
- 动态经验分配
- 经验追赶机制

**经验来源表：**

| 来源 | 经验值 | 频率 | 策略价值 |
|------|--------|------|----------|
| 被动经验 | 23点/秒 | 持续 | 基础发育 |
| 小兵 | 80点/个（每分钟+2点）* | 持续 | 主要经验来源 |
| 雇佣兵营地 | 固定经验 | 中等 | 资源争夺 |
| 防御塔 | 固定经验** | 低 | 推进奖励 |
| 堡垒/要塞 | 被动经验+20% | 低 | 长期收益 |
| 英雄击杀 | 250+50×目标等级* | 低 | 团战奖励 |
| 地图目标 | 固定经验 | 极低 | 战略关键点 |
| 召唤单位 | 不给经验 | - | 特殊机制 |
| 其他建筑（墙壁、大门、治疗喷泉） | 无经验 | - | 无经验奖励 |

*英雄击杀经验为全局经验，无论距离如何都能获得；英雄死亡于中立野怪不给经验，除非有英雄获得击杀或助攻

*每波小兵共7个，其中6个近战和远程小兵各给80 XP（在Tomb of the Spider Queen地图上为68 XP），每波总经验约480+ XP（Tomb of the Spider Queen约408 XP）
**防御塔在被摧毁时给予固定经验，无论是否有英雄在附近

**玩家视角：**
- 屏幕上方显示团队经验条，对比双方差距
- 击杀、推塔时获得即时反馈（经验值飘字，金色数字）
- 经验落后时UI提示，激励追分
- 团队成员分散在不同路线时，可以同时收集多条路线的经验，但每个经验事件只计算一次
- 落后团队击杀敌方英雄时获得经验加成
- 召唤单位（如Azmodan的恶魔）可以通过最后一击帮助收集小兵经验

**关键机制：**
- **团队共享经验**：所有玩家共享同一个经验池，全员同步升级
- **经验球收集(soaking)**：小兵被非英雄单位击杀后掉落经验球，非潜行状态且不在草丛中的英雄会从相当大的半径范围内自动吸引并收集经验球
- **最后一击**：英雄直接用技能或普通攻击击杀小兵，无需收集经验球，直接获得经验，无距离限制
- **经验追赶**：落后团队仅对击杀敌方英雄获得经验加成，领先团队获得经验减少。经验追赶机制考虑双方队伍的XP进度，而不仅仅是等级差距
- **被动经验**：每秒获得23点经验，从大门开启后35秒开始
- **经验上限**：团队等级最高可达30级
- **建筑加成**：摧毁堡垒或要塞后，被动经验获取速度增加20%/个，每个加成约相当于每2分钟一波小兵的经验
- **防御塔经验**：防御塔在被摧毁时给予固定经验，无论是否有英雄在附近；堡垒和要塞不直接给经验，而是增加被动经验获取速度；墙壁、大门和治疗喷泉不给经验
- **召唤单位经验**：召唤单位（除Misha外）死亡不给经验，但可以通过最后一击从小兵身上收集经验，召唤单位不能收集经验球

### 3.2 召唤单位经验机制

**功能描述：**
- 英雄召唤的单位（除Misha外）死亡时不给敌方经验
- 召唤单位可以通过最后一击从小兵身上收集经验
- 召唤单位不能收集经验球（只有英雄宠物可以）

**召唤单位经验规则表：**

| 行为 | 是否给经验 | 说明 |
|------|-----------|------|
| 召唤单位死亡 | 否 | 英雄召唤的单位（Misha除外）死亡不给敌方经验 |
| 召唤单位最后一击小兵 | 是 | 召唤单位直接击杀小兵可获得经验，无距离限制 |
| 召唤单位收集经验球 | 否 | 召唤单位不能收集经验球（只有英雄宠物可以） |
| Misha死亡 | 是 | Misha作为Rexxar的英雄宠物，死亡会给经验 |

**玩家视角：**
- 使用召唤单位（如Azmodan的恶魔）可以安全地收集小兵经验
- 召唤单位死亡不会给敌方团队提供经验优势
- 长距离技能英雄可以通过召唤单位远程收集经验

**开发视角：**
```python
class SummonedUnit:
    def __init__(self, owner, unit_type):
        self.owner = owner
        self.unit_type = unit_type
        self.can_collect_exp_globs = False  # 召唤单位不能收集经验球
        self.can_last_hit = True  # 召唤单位可以最后一击
        self.gives_exp_on_death = False  # 死亡不给经验（Misha除外）

    def on_minion_death(self, killing_blow):
        if killing_blow and self.can_last_hit:
            # 召唤单位最后一击小兵，给团队经验
            exp = self.get_minion_exp_value()
            self.owner.team.add_experience('minion', exp)

    def on_death(self, killer):
        if self.gives_exp_on_death:
            # Misha等特殊单位死亡会给经验
            exp = self.get_exp_value()
            killer.team.add_experience('summoned_unit', exp)
```

**关键机制：**
- **远程经验收集**：Azmodan等英雄可以通过召唤单位远程收集小兵经验
- **安全发育**：召唤单位死亡不会给敌方经验，降低发育风险
- **战略价值**：召唤单位可以同时承担战斗和经验收集任务
- **Misha例外**：作为Rexxar的英雄宠物，Misha死亡会给敌方经验

### 3.4 天赋系统

**功能描述：**
- 替代装备系统
- 每级提供3-5个天赋选项
- 天赋分支形成不同流派
- 每个英雄拥有独特的天赋树

**天赋解锁等级：**
- 1级：第一层天赋
- 4级：第二层天赋
- 7级：第三层天赋
- 10级：终极技能（Heroic Ability）
- 13级：第四层天赋
- 16级：第五层天赋
- 20级：终极天赋（Storm Talent）

**天赋类型表：**

| 天赋类型 | 占比 | 功能 | 示例 |
|----------|------|------|------|
| 功能型 | 30% | 增强技能机制 | 减少冷却、增加范围 |
| 数值型 | 25% | 提升属性 | 增加伤害、护盾值 |
| 生存型 | 20% | 增强续航 | 生命回复、减伤 |
| 辅助型 | 15% | 团队增益 | 移速加成、视野 |
| 终极型 | 10% | 改变玩法 | 全新终极技能 |

**玩家视角：**
- 天赋界面显示天赋图标、名称、描述
- 鼠标悬停显示详细效果和数值
- 已选天赋在左侧栏显示，形成"天赋树"
- 部分天赋会改变英雄的视觉效果

**开发视角：**
```python
class TalentSystem:
    def __init__(self, hero):
        self.hero = hero
        self.selected_talents = {}
        self.available_talents = self.load_talent_tree(hero.name)  # 每个英雄有独特天赋树

    def get_talents_at_level(self, level):
        return self.available_talents.get(level, [])

    def select_talent(self, level, talent_id):
        if talent_id in self.get_talents_at_level(level):
            self.selected_talents[level] = talent_id
            self.apply_talent_effect(talent_id)

    def apply_talent_effect(self, talent_id):
        talent = self.get_talent_data(talent_id)
        # 根据天赋类型应用不同效果
        if talent.type == 'stat_boost':
            self.hero.stats[talent.stat] += talent.value
        elif talent.type == 'skill_mod':
            self.hero.skills[talent.skill].modify(talent.modifier)
        elif talent.type == 'visual_change':
            self.hero.model.apply_visual_effect(talent.visual_effect)
```

**关键机制：**
- **英雄独特性**：每个英雄有自己的天赋树，确保英雄玩法多样性
- **天赋共享**：部分基础天赋（如+20攻击）可能在多个英雄间共享
- **视觉反馈**：部分天赋会改变英雄的视觉效果，增强游戏体验
- **战略选择**：不同等级的天赋选择会影响英雄的发展方向

**一句话总结：** 经验获取→团队共享→升级触发→天赋选择→效果应用的完整流程，确保所有玩家同步成长。

### 4.1 经验获取流程

```
[游戏事件触发]
    ↓
[判断事件类型]
    ├─ 小兵死亡 → 掉落经验球/最后一击 → 团队经验池
    ├─ 野怪击杀 → 直接获得经验 → 团队经验池
    ├─ 英雄击杀 → 直接获得经验（可能有经验追赶加成） → 团队经验池
    ├─ 防御塔摧毁 → 固定经验 → 团队经验池
    ├─ 堡垒/要塞摧毁 → 被动经验+20% → 团队经验池
    ├─ 地图目标 → 直接获得经验 → 团队经验池
    └─ 时间流逝 → 被动经验（23点/秒） → 团队经验池
    ↓
[更新团队经验条]
    ↓
[检查是否达到升级阈值]
    ├─ 否 → 等待下次经验
    └─ 是 → 触发升级
```

**关键机制说明：**
- **经验球机制(soaking)**：小兵被非英雄单位击杀后掉落经验球，非潜行状态且不在草丛中的英雄会从较远范围自动吸引并收集经验球

**界面设计：**
- **位置**：屏幕顶部中央，占据屏幕宽度的80%

  - 队伍头像：显示双方英雄头像

```python
class ExperienceUI:
    def update_experience_bars(self, blue_exp, red_exp, game_time):
        # 更新队伍等级显示
        self.blue_level.text = f"{blue_exp.level}"
        self.red_level.text = f"{red_exp.level}"
        
        # 更新游戏时间
        self.game_time.text = self.format_time(game_time)
        
        # 计算并显示等级差距
        level_diff = blue_exp.level - red_exp.level
        if level_diff > 0:
            self.blue_level.set_style("leading")  # 突出显示领先方
            self.red_level.set_style("normal")
        elif level_diff < 0:
            self.red_level.set_style("leading")  # 突出显示领先方
            self.blue_level.set_style("normal")
        else:
            self.blue_level.set_style("normal")
            self.red_level.set_style("normal")
        
        # 检查并显示追赶状态
        if blue_exp.level < red_exp.level:
            self.show_catchup_indicator("blue")
        elif red_exp.level < blue_exp.level:
            self.show_catchup_indicator("red")
        else:
            self.hide_catchup_indicator()
```

## 五、数值模型

**一句话总结：** 通过非线性升级曲线、经验追赶机制、天赋强度平衡，确保游戏节奏和竞技公平性。

- 被动经验：23点/秒
- 升级间隔：前期1.5-2分钟，后期3-4分钟
- 总游戏时长：20-30分钟

### 5.2 经验追赶机制

**追赶公式：**
- 落后方：1-4级差距分别获得10%、30%、60%、100%经验加成
- 领先方：1-4级优势分别获得10%、30%、60%、95%经验减少

**重要说明：**
- 经验追赶加成**仅适用于击杀敌方英雄**
- 小兵、野怪、建筑等其他经验来源不受此机制影响
- 追赶机制考虑双方队伍的XP进度，而不仅仅是等级差距

**追赶效果表：**

| 等级差距 | 落后方加成 | 领先方减少 | 追赶所需时间 |
|----------|------------|------------|--------------|
| 1级 | +10% | -10% | 3-4分钟 |
| 2级 | +30% | -30% | 4-5分钟 |
| 3级 | +60% | -60% | 5-6分钟 |
| 4级+ | +100% | -95% | 6-8分钟 |

**玩家视角：**
- 落后时UI显示"经验追赶中"
- 经验获取时飘字显示加成倍率
- 追赶上后提示"经验差距已消除"

**开发视角：**
- 追赶机制防止过早失去悬念
- 最大加成限制防止反噬
- 动态调整确保游戏不会拖沓

### 5.3 天赋强度平衡

**天赋强度评估模型：**

```
天赋强度 = (数值提升 × 权重1) + (机制改变 × 权重2) + (战略价值 × 权重3)

其中：
- 数值提升：直接属性加成（伤害、护盾、冷却等）
- 机制改变：技能机制变化（范围、次数、条件等）
- 战略价值：对团队战术的影响（开团、反打、推进等）

权重：权重1=0.3, 权重2=0.4, 权重3=0.3
```

**天赋强度分级表：**

| 强度等级 | 分数范围 | 占比 | 示例 |
|----------|----------|------|------|
| S级 | 85-100 | 5% | 终极天赋、机制质变 |
| A级 | 70-84 | 15% | 强力数值天赋 |
| B级 | 55-69 | 40% | 标准天赋 |
| C级 | 40-54 | 30% | 弱化天赋 |
| D级 | 0-39 | 10% | 填充天赋 |

**平衡策略：**
- 每级天赋强度总和相近（±5%）
- 同级天赋提供不同方向选择
- 避免出现"必选天赋"
- 定期根据数据调整天赋数值

### 5.4 参数方案对比

| 参数 | 保守方案 | 标准方案 | 激进方案 |
|------|----------|----------|----------|
| 升级速度 | 慢25% | 标准 | 快25% |
| 追赶加成 | 最大1.5x | 最大2.0x | 最大2.5x |
| 天赋多样性 | 每级3个 | 每级4个 | 每级5个 |
| 游戏时长 | 25-30分钟 | 20-25分钟 | 15-20分钟 |
| 适用场景 | 竞技比赛 | 标准匹配 | 快速模式 |

## 七、风险与迭代

**一句话总结：** 团队共享经验系统存在"个人贡献感弱"、"天赋多样性不足"、"平衡性挑战"等风险，需通过持续数据监控和玩家反馈迭代优化。

### 7.1 设计风险

| 风险类型 | 风险描述 | 影响等级 | 应对策略 |
|----------|----------|----------|----------|
| 贡献感弱 | 玩家难以感知个人贡献 | 高 | 增加个人统计展示、MVP系统 |
| 天赋单一 | 容易形成最优解 | 高 | 定期调整天赋、增加多样性 |
| 平衡困难 | 天赋组合难以平衡 | 中 | 建立数据监控、快速迭代 |
| 节奏拖沓 | 天赋选择时间过长 | 中 | 缩短选择时间、增加预设 |
| 学习成本 | 天赋系统复杂 | 低 | 提供推荐天赋、新手引导 |

### 7.2 迭代方向

**短期优化（1-3个月）：**
- 优化天赋选择UI，增加推荐功能
- 调整部分过强/过弱天赋
- 增加个人贡献统计展示

**中期优化（3-6个月）：**
- 引入天赋预设系统
- 增加动态天赋（根据局势变化）
- 优化经验追赶机制

**长期优化（6-12个月）：**
- 引入英雄专属天赋系统
- 增加天赋组合协同效果
- 探索更多成长维度

### 7.3 数据监控指标

**关键指标表：**

| 指标 | 合格线 | 优秀线 | 监控频率 |
|------|--------|--------|----------|
| 天赋多样性 | >60% | >75% | 每周 |
| 升级节奏一致性 | ±10% | ±5% | 每周 |
| 经验追赶成功率 | >40% | >55% | 每周 |
| 天赋选择时间 | <10秒 | <7秒 | 每周 |
| 玩家满意度 | >70% | >85% | 每月 |

## 八、为什么不同于其他MOBA？

**一句话总结：** 风暴英雄的经验系统设计源于"团队协作大于个人能力"的核心理念，通过消除个体差异来提升策略深度和观赏性。

### 8.1 设计哲学差异

| 维度 | 传统MOBA | 风暴英雄 |
|------|----------|----------|
| 核心理念 | 个人英雄主义 | 团队协作 |
| 成长方式 | 装备+等级 | 天赋系统 |
| 滚雪球 | 设计特色 | 故意避免 |
| 游戏节奏 | 慢热发育 | 快速团战 |
| 观赏性 | 个人操作秀 | 团队配合 |

### 8.2 设计动机分析

**1. 降低学习门槛**
- 传统MOBA：需要学习补刀、装备购买、经济管理等多重系统
- 风暴英雄：只需关注天赋选择和团队配合
- 效果：新手玩家上手时间缩短

**2. 强化团队协作**
- 传统MOBA：辅助位经济经验双重劣势，容易产生挫败感
- 风暴英雄：所有角色平等成长，鼓励团队配合
- 效果：团队配合度要求提升，玩家留存率提高，

**3. 提升观赏性**
- 传统MOBA：个人优势快速扩大，比赛悬念提前消失
- 风暴英雄：团队优势需持续积累，比赛悬念保持时间更长最后
- 效果：电竞比赛平均时长缩短，精彩程度提升

**4. 加快游戏节奏**
- 传统MOBA：发育期10-15分钟，总时长30-45分钟
- 风暴英雄：发育期3-5分钟（甚至没有发育期），总时长20-25分钟
- 效果：玩家日均对局数提升

### 8.3 设计优势与劣势

**优势：**
1. **降低挫败感**：即使被压制也能通过团队贡献获得成长
2. **提升策略深度**：天赋系统提供更多策略选择
3. **强化团队配合**：所有角色平等，鼓励协作
4. **加快游戏节奏**：缩短发育期，更快进入团战
5. **提升观赏性**：比赛悬念保持到最后

**劣势：**
1. **个人贡献感弱**：难以感知个人对团队的贡献
2. **天赋多样性挑战**：容易形成最优解
3. **平衡性困难**：天赋组合难以平衡
4. **上限相对较低**：个人操作上限不如传统MOBA
5. **玩家群体分化**：部分传统MOBA玩家不适应

### 8.4 适用场景分析

**适合场景：**
- 休闲玩家：降低学习门槛，减少挫败感
- 团队游戏：强调团队协作，适合朋友开黑
- 电竞比赛：提升观赏性，比赛悬念保持
- 移动端适配：简化系统，适合移植

**不适合场景：**
- 硬核玩家：个人操作上限较低
- 长期留存：天赋多样性不足
- 竞技深度：策略深度不如传统MOBA

## 九、总结

风暴英雄的经验系统设计是一次大胆的创新，通过团队共享经验、天赋系统替代装备、经验追赶机制等设计，成功实现了以下目标：

1. **降低学习门槛**：简化经济系统，让新手更快上手
2. **强化团队协作**：所有角色平等成长，鼓励团队配合
3. **提升观赏性**：比赛悬念保持到最后，电竞观赏性更强
4. **加快游戏节奏**：缩短发育期，更快进入团战博弈

**核心机制特点：**
- **团队共享经验**：所有玩家共享同一个经验池，全员同步升级
- **经验球机制**：小兵死亡后掉落经验球，英雄在范围内自动收集
- **经验丢失**：小兵掉落的经验球不及时收集会缩小直至消失
- **经验追赶**：落后团队获得击杀敌方英雄的经验加成，领先团队获得经验减少
- **被动经验**：每秒获得23点经验，从游戏开始35秒后开始
- **经验上限**：团队等级最高可达30级
- **建筑加成**：摧毁堡垒或要塞后，被动经验获取速度增加20%/个
- **独特天赋系统**：每个英雄拥有独特的天赋树，部分天赋完全改变英雄机制玩法
- **直观界面**：顶部显示双方等级对比和游戏时间，清晰传达团队状态

**界面设计特点：**
- **简洁明了**：顶部显示双方英雄头像、等级和游戏时间
- **信息清晰**：等级对比直接显示，一目了然
- **交互友好**：鼠标悬停显示详细信息，点击展开统计面板
- **状态反馈**：领先方等级突出显示，追赶状态有明确提示

这种设计虽然牺牲了一定的个人操作上限和深度，但换来了更广泛的受众群体和更激烈的团队博弈，为MOBA游戏提供了另一种可能性。

对于游戏开发者而言，风暴英雄的经验系统证明了：**打破常规、重新思考核心循环，可以创造出完全不同的游戏体验**。关键是要明确自己的目标用户和核心体验，然后围绕这个核心进行系统性创新。

# 风暴英雄经验系统拆解

## 1. 经验系统概述

风暴英雄的经验系统与传统MOBA游戏有很大不同，主要体现在团队共享经验上。这种设计理念彻底改变了游戏的节奏和策略，让团队合作变得更加重要。

## 2. 经验获取机制

### 2.1 团队共享经验
- 所有队员获得相同的经验值
- 击杀小兵、野怪和英雄的经验全队共享
- 等级统一，避免了传统MOBA中个别玩家等级落后的情况

### 2.2 地图目标经验
- 地图特定目标提供大量经验奖励
- 如巨龙镇的龙骑士、花村的运载目标等
- 这些目标往往成为游戏的转折点

### 2.3 小兵和野怪经验
- 小兵提供稳定的经验来源
- 野怪营地提供额外的经验和增益效果
- 合理的刷野路线可以帮助团队建立等级优势

## 3. 对游戏节奏的影响

### 3.1 团战频率
- 由于经验共享，团队需要经常一起行动
- 单独行动的风险更高，因为等级差距会很快显现
- 团战成为获取经验和地图目标的主要方式

### 3.2 地图目标争夺
- 地图目标的经验奖励使得争夺更加激烈
- 目标刷新时间成为游戏的关键节点
- 围绕目标的团战往往决定游戏的走向

### 3.3 雪球效应控制
- 等级领先的优势相对可控
- 落后团队仍有机会通过争夺地图目标扳回局势
- 游戏后期的经验获取速度加快，有利于翻盘

## 4. 战略意义

### 4.1 等级领先的优势
- 技能等级提升带来的伤害和生存能力提升
- 终极技能（R技能）的提前解锁
- 对地图目标的控制力增强

### 4.2 团队配合的重要性
- 经验共享强调团队整体表现
- 个人英雄主义的空间减小
- 沟通和协调成为取胜的关键

### 4.3 翻盘的可能性
- 后期地图目标的经验奖励巨大
- 一次成功的团队团战可以迅速缩小等级差距
- 游戏的悬念和观赏性提高

## 5. 与传统MOBA的对比

### 5.1 传统MOBA经验系统
- 个人获取个人击杀的经验
- 等级差异可能很大
- 单线优势可以转化为全局优势

### 5.2 风暴英雄的优势
- 减少了雪球效应
- 增强了团队合作
- 地图目标更加重要
- 游戏节奏更加紧凑

## 6. 结论

风暴英雄的经验系统设计是其独特性的核心之一。通过团队共享经验，游戏强调了合作的重要性，创造了更加团队导向的游戏体验。这种设计不仅改变了游戏的玩法，也为MOBA游戏的发展提供了新的思路。

经验系统的设计体现了风暴英雄的整体理念：注重团队合作、强调地图目标、创造更加公平和激动人心的游戏体验。这也是为什么尽管游戏已经运营多年，仍然有许多玩家对其系统设计赞赏有加的原因。
